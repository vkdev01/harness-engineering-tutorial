Sonnet 4.5 scored 77.2% on SWE-bench Verified. Then you hand it your actual repo and it confidently ships something broken. The gap has a name: the capability gap.

People say "harness" and mean "the system prompt I wrote." That is one of five subsystems. The other four are where most reliability actually comes from.

A new engineer joins your project with no README, no comments, nobody to ask, and CI config buried somewhere. Smart people still struggle. An agent has it worse: it can only see the files you put in front of it and the commands it can run.

The repo is the spec. Anything the agent cannot see in the repository does not exist for it.

InstructionsRules, conventions, definition of done — AGENTS.md
ToolsWhat it can actually do — shell, test runner, linters
EnvironmentA runnable, isolated place to work — init.sh
StateWhat is done, why, and what is next — feature_list.json
FeedbackEvidence of what happened — tests, traces, logs

Score each one honestly. The lowest score is your ceiling, not the average — a harness is a chain, and a brilliant instruction file cannot rescue an agent that cannot run the tests.

Exercise 02.1interactive

Rate the repo you use an agent on most often. 0 means it does not exist; 4 means solid and maintained.

  • 0–1 — absent or aspirational. This is your ceiling.
  • 2 — exists, but nobody verifies it still works.
  • 3–4 — maintained, and used on every session.

The readout reports the minimum, not the mean. Average the five and you will always feel fine about a harness that is failing.
