Chapter 02 · Definition

A prompt file is not a harness.

People say "harness" and mean "the system prompt I wrote." That is one of five subsystems. The other four are where most reliability actually comes from.

The analogy that makes it click: a new engineer joins your project with no README, no comments, nobody to ask, and CI config buried somewhere. Smart people still struggle — they spend their day working out what the project is instead of solving the problem. An agent has it worse: it can only see the files you put in front of it and the commands it can run.

OpenAI frames the core principle as the repo is the spec. Anthropic frames it as state persistence and explicit recovery paths. Different words, same claim: everything outside the model weights decides how much of the model's capability actually gets realised.

Marginal note Remove one subsystem at a time and re-run the same task. Whichever removal hurts most is the one to invest in next.

2.1The five subsystems

SubsystemWhat it carriesTypical artefacts
InstructionsRules, conventions, definition of doneAGENTS.md, docs/
ToolsWhat the agent can actually doshell, test runner, linters, MCP
EnvironmentA runnable, isolated place to workinit.sh, lockfiles, worktrees
StateWhat is done, why, and what is nextfeature_list.json, progress log
FeedbackEvidence of what actually happenedtests, type checks, traces, logs

Three habits separate a real harness from a prompt dump. Give a map, not a manual. Constrain, don't micromanage. And measure what each part is worth rather than assuming.

2.2Why the weakest link wins

A harness is a chain. A brilliant instruction file cannot rescue an agent that cannot run the tests; a perfect test suite does nothing if the agent never learns what state it is in. Adding strength anywhere else is mostly wasted effort until the weakest layer is fixed.

Chapter 03 · Instructions

If it isn't in the repo, it doesn't exist.

An agent has three inputs: the task description, the contents of the repository, and the output of commands it runs. Slack, Jira and the decision you made on Friday are all invisible to it.

This is not a "write more documentation" problem. It is a "put the decision where it will be needed" problem. A 50-line ARCHITECTURE.md inside src/api/ beats a 500-page wiki nobody maintains, because information only helps at the moment it is in front of the reader.
