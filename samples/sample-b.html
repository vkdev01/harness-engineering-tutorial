Chapter 02 · Definition

A prompt file is not a harness.

People say "harness" and mean "the system prompt I wrote." That is one of five subsystems. The other four are where most reliability actually comes from.

A new engineer joins your project with no README, no comments, nobody to ask, and CI config buried somewhere. Smart people still struggle — they spend the day working out what the project is instead of solving the problem. An agent has it worse: it can only see the files you put in front of it and the commands it can run.

Key idea The repo is the spec. Anything the agent cannot see in the repository does not exist for it — no matter how obvious it is to your team.

2.1The five subsystems

Instructions
Rules, conventions, definition of done — AGENTS.md
Tools
What the agent can actually do — shell, test runner, linters
Environment
A runnable, isolated place to work — init.sh, lockfiles
State
What is done, why, and what is next — feature_list.json
Feedback
Evidence of what actually happened — tests, traces

2.2Why the weakest link wins

A harness is a chain. A brilliant instruction file cannot rescue an agent that cannot run the tests; a perfect test suite does nothing if the agent never learns what state it is in. Adding strength anywhere else is wasted until the weakest layer is fixed.
